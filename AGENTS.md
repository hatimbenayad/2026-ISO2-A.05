# AGENTS.md — AI Engineering Guidelines and Operational Rules
Project: Radiodiagnostic Clinical Management System (ISO2 2026/27 — Group A.05)
Repository: https://github.com/hatimbenayad/2026-ISO2-A.05

This document defines the strict operational rules, architectural constraints, and coding standards that every AI assistant (GitHub Copilot, Gemini CLI, Claude Code) must follow when generating code, tests, or documentation for this project.

---

## 1. Core Principles and Governance
1. Spec-Driven Development (D-014): Human engineers design interfaces and test cases. AI assistants implement contracts and generate supporting boilerplate.
2. Human-in-the-Loop (HITL): No code or documentation generated by AI may be merged without human peer review and verification.
3. Academic Integrity and Anti-Plagiarism Policy:
   - The instructor's reference repository (https://github.com/IsmaelCaballero/PrISO2-25-26) serves EXCLUSIVELY as high-level architectural inspiration.
   - ZERO COPYING: AI assistants must NEVER copy, extract, adapt, or import any code, text, files, issues, or wiki content from the reference repository. All Group A.05 deliverables must be independently authored.

---

## 2. Technical Stack and Build Standards
- Language: Java 21 (LTS).
- Build System: Apache Maven 3.9+ via Maven Wrapper (./mvnw or mvnw.cmd).
- Architecture (D-017): Multi-module layout:
  - common-contracts: Shared DTOs, domain interfaces, and exception types (zero framework dependencies).
  - server: Business services, persistence repositories, and backend controllers.
  - client: Swing desktop user interface components.
- Testing Framework: JUnit 5 (Jupiter), AssertJ, and JaCoCo coverage (minimum 80% line coverage gate).
- Precision and Time Arithmetic: Currency and pricing arithmetic must strictly use java.math.BigDecimal with String constructors and RoundingMode.HALF_UP. Date and time operations must strictly use java.time types (LocalDateTime, Duration).

---

## 3. Clinical and Business Domain Rules
- Non-Destructive Operations (D-015): Clinical records, patient appointments, and diagnostic orders must NEVER undergo physical SQL DELETE. Deactivations and cancellations must record timestamps (cancelledAt, deactivatedAt) alongside status transitions (CANCELLED, INACTIVE) to guarantee medical auditability.
- Strict Tier Decoupling: Domain logic and business services must NEVER import or reference presentation classes (javax.swing.*, java.awt.*, or CLI scanner classes).

---

## 4. GitFlow and Contribution Discipline
- Target Branch: All feature development branches off develop and targets develop. NEVER open pull requests against main.
- Branch Naming: Strictly feature/<descriptive-name>, bugfix/<name>, or hotfix/<name>.
- Branch Preservation: Remote branches are NEVER deleted after merging (Kickoff Slide 9).
- Conventional Commits: Commit messages must strictly follow:
  type(scope): concise imperative description (closes #X)
  Allowed types: feat, fix, docs, test, refactor, build, ci.
- Peer Review Gate: All pull requests require green CI (mvn -B verify) and peer review before merging into develop.
